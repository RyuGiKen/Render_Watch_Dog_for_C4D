【内层 · 一个进程的观察】 异常计数=0、记录已落定进度；启动后每 30s 轮询（无进程已退出的加载误判风险）：
等待30s(可中断)① 收到停止 → 杀进程树 → 返回「停止」
② 块内全部落定？是 → 若进程还在则杀「渲完未退出」，否则正常退出 → 返回「成功」
③ 有新帧落定？是 → 重置「无进展计时」，视为有进展
④ 崩溃报告在195s时窗内 或 进程已退出但块未全落定 或 600s无新帧落定？是 → 异常计数 +1（X/5）；=5 → 杀进程树 返回「尝试失败」
⑤ 已退出且块内已有部分落定立即 返回「尝试失败」（外层前进到缺口续渲，不空等去抖）
⑥ 仅无响应(未无进展超时)仅Cinema4D可观测，Commandline恒跳过；只提示一次，异常计数清零 → 等下一tick
⑦ 以上都不成立(正常推进)异常计数保持/清零 → 等下一tick
"落定"= 产物存在·非空·距最后写入≥帧间冷却(60s)（预留写入等待，防半截文件）；空/半截不算落定，崩在帧7会留下→下块起点自动落到7。

预览按钮（单帧面板）

按命名规则（*→等长?通配）匹配，用正则从占位位置解析帧号；多通道带前后缀因整名不匹配、解析不出帧号 → 不计入。数量 X = 识别出的帧号个数；把帧号合并成连续段、落在 * 位显示：
全连续：Image_[0,100].png 等101个文件
缺 60：Image_[0,59].png，Image_[61,100].png 等100个文件
孤立单帧段：Image_[7].png（start==end 不写 7,7）

日志上限（防长跑占内存）

• 累计超过 1500 行 或 15 万字符时，裁掉最旧部分、保留末尾约 1000 行；只影响显示，不影响判定。

关键要点

• 统一模型：N=1 退化为单帧（块=[a,a]），单帧/分块同一套代码。
• 挂起：由"每帧总超时"改为600s 无新帧落定；块多长都不误杀，块内卡死也能及时抓。无响应仍只提示、不杀（Commandline 无窗口自动跳过）。
• 报错(崩溃报告)：195s 时窗命中即+1、达最大异常次数(5)才杀、出窗清零——与①同款去抖。
• 推进/跳过：前进就重置焦点失败计数；原地卡满帧最大失败(4)才跳起点帧，游标只前进不留内部洞；跨重启不留痕、用户手填范围。连续3块原地即失败→熔断停止。
• 冷却：每块启动前空载冷却(无渲染)；块内 N 帧连渲无冷却，N 越大越省加载也越积热。
• 范围夹取：所有帧号/块端点自动夹进 [起始帧, 结束帧]，N 允许 ≥ 总帧数一次渲完。
